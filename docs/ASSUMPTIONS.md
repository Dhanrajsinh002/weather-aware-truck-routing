# Implemented Business Assumptions & Rules

The table below documents every rule left open or ambiguous in the specification, detailing how it is implemented in the codebase, its exact file location, and the automated test proving it.

| Rule Category | Implemented Rule Description | Implementation Location | Verification Test |
|---|---|---|---|
| **Wind Boundaries** | `<25` mph = LOW (0); `[25, 35)` = MODERATE (1); `[35, 45)` = HIGH (2); `[45, 55)` = SEVERE (3); `≥55` = NO_TRAVEL (4). Exact boundaries (25.0, 35.0, 45.0, 55.0) transition to the higher risk category. | `backend/core/risk.py`<br>`classify_wind()` | `test_risk.py`<br>`test_classify_wind_boundaries` |
| **Rain Boundaries** | `<0.10` in/hr = LOW (0); `[0.10, 0.25]` = MODERATE (1); `(0.25, 0.50]` = HIGH (2); `(0.50, 1.00]` = SEVERE (3); `>1.00` = NO_TRAVEL (4). Exactly 0.25 is MODERATE; exactly 1.00 is SEVERE. | `backend/core/risk.py`<br>`classify_rain()` | `test_risk.py`<br>`test_classify_rain_boundaries` |
| **Snow Boundaries** | `<0.5` in/hr = LOW (0); `[0.5, 1.0]` = MODERATE (1); `(1.0, 2.0]` = HIGH (2); `(2.0, 3.0]` = SEVERE (3); `>3.0` = NO_TRAVEL (4). Exactly 1.0 is MODERATE; exactly 3.0 is SEVERE. | `backend/core/risk.py`<br>`classify_snow()` | `test_risk.py`<br>`test_classify_snow_boundaries` |
| **Sustained vs Gusts** | Maximum effective wind is taken: `effective_wind = max(wind_mph, gust_mph)`. If either sustained wind or gust breaches a threshold, the higher risk applies. | `backend/core/risk.py`<br>`classify_checkpoint_risk()` | `test_risk.py`<br>`test_classify_checkpoint_calm` |
| **Precipitation Field Mapping** | Open-Meteo mm and cm are converted to inches: `rain_in_hr = (rain + showers) * 0.0393701`; `snow_in_hr = snowfall * 0.393701`. Both large-scale rain and convective showers are combined. | `backend/providers/open_meteo.py`<br>`_parse_response()` | `test_open_meteo.py`<br>`test_parse_open_meteo_fixture` |
| **Commercial Load Blowover Rules** | `wind ≥ 55 mph`: NO_TRAVEL for any load.<br>`wind in [45, 55) mph` and `load > 30,000 lb`: escalates from SEVERE to NO_TRAVEL.<br>`wind in [35, 45) mph` and `load > 40,000 lb`: escalates from HIGH to SEVERE.<br>Load rules only escalate, never downgrade. | `backend/core/risk.py`<br>`apply_load_rules()` | `test_risk.py`<br>`test_apply_load_rules_boundaries`<br>`test_load_never_lowers_level` |
| **Hourly Weather Interpolation** | Linear interpolation between hourly brackets: $W(t) = W_0 + (W_1 - W_0) \times (t - t_0) / 3600$. Before forecast start: clamped to earliest hour. Beyond 168h horizon: clamped to last available hour. | `backend/core/weather_interp.py`<br>`interpolate_weather_at_time()` | `test_weather_interp.py`<br>`test_interpolate_half_hour`<br>`test_before_horizon_clamping`<br>`test_after_horizon_clamping` |
| **Intervals & Auto Rule** | User selects 10, 25, 50, or "auto". Auto rule selects: `<150 mi` -> 10 mi; `150-500 mi` -> 25 mi; `>500 mi` -> 50 mi. Start (mile 0) and final destination checkpoint are always guaranteed. | `backend/core/geo.py`<br>`auto_interval_miles()`<br>`sample_checkpoints()` | `test_geo_sampling.py`<br>`test_auto_interval`<br>`test_sample_checkpoints_spacing_and_endpoints` |
| **Segment Ownership** | Checkpoint $i$ at distance $d_i$ owns segment between Voronoi midpoints: $[(d_{i-1}+d_i)/2, (d_i+d_{i+1})/2]$, clamped to $[0, D]$. Sum of owned segment lengths exactly equals route distance. | `backend/core/metrics.py`<br>`compute_segment_ownership()` | `test_metrics.py`<br>`test_segment_ownership_hand_computed` |
| **Risk Miles Aggregation** | Each checkpoint's owned mileage is attributed to its classified risk level (`no_travel_miles`, `severe_miles`, `high_miles`). | `backend/core/metrics.py`<br>`compute_route_metrics()` | `test_metrics.py`<br>`test_route_metrics_hand_computed` |
| **Average Risk Calculation** | Distance-weighted mean of numerical risk scores (0 to 4): $\sum (\text{level}_i \times \text{miles}_i) / D$, rounded to 2 decimal places. | `backend/core/metrics.py`<br>`compute_route_metrics()` | `test_metrics.py`<br>`test_route_metrics_hand_computed` |
| **Ranking Order & Tie-Breaks** | Lexicographic sort key: `(no_travel_miles, severe_miles, high_miles, avg_risk, duration_seconds)`. Lowest tuple ranks first (`rank = 1`). Duration breaks safety ties. | `backend/core/recommend.py`<br>`rank_and_recommend()` | `test_recommend.py`<br>`test_rule_1_prefers_fewer_no_travel_miles`<br>through `test_rule_5_prefers_shorter_duration` |
| **No Travel Handling** | If any route has 0 No-Travel miles, routes with No-Travel conditions are rejected from recommendation. If all routes encounter No-Travel, best available is recommended with an explicit safety warning to delay departure. | `backend/core/recommend.py`<br>`rank_and_recommend()` | `test_recommend.py`<br>`test_all_routes_contain_no_travel_triggers_warning` |
| **Validation Boundaries** | Latitude: `[-90.0, 90.0]`; Longitude: `[-180.0, 180.0]`. Load weight: `[1.0, 100,000.0]` lb. Departure time: valid ISO8601 string, must be $\ge$ `now - 15 minutes` to allow slight network variance. | `backend/api/serializers.py`<br>`AnalyzeRequestSerializer` | `test_api_analyze.py`<br>`test_analyze_validation_errors` |
| **Time Zone Handling** | All backend calculations and JSON contracts use explicit ISO8601 UTC timestamps (`YYYY-MM-DDTHH:MM:SSZ`). Frontend converts to user local time for UI display and slider scrubbing. | `backend/core/eta.py`<br>`backend/services/analyze.py` | `test_eta.py`<br>`test_eta_endpoints_exact_proportional` |
